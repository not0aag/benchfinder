# Data quality feedback loop

## Submission outcomes
Every submission response must include one explicit outcome:
- accepted
- accepted_unconfirmed
- held_for_review
- rejected_duplicate
- rejected_quality

## Contributor-facing messages
- Explain why a submission was held or rejected using one primary reason code.
- Include one corrective action in plain language.
- Keep moderation copy localized via i18n keys.

## Trust and verification visibility
- Show verification state on every bench detail surface.
- Show confirmation and dispute counts to explain confidence.
- Show whether provenance is OSM-seeded or user-contributed.
